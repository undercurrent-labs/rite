# E021 — an effect needs a marker

Rite marks host effects where they happen. `E021` is raised whenever an effect
would occur without one — and, in the last shape below, when a marker claims an
effect that does not.

## A host call with no marker

```rite compile_fail
@console.println("x")
```

```rite exec
! @console.println("x")
```

## A function whose body performs effects, undeclared

Reported at the declaration rather than at every call, so the fix is one edit:

```rite compile_fail
◆ greet(name) ⟦
  ! @console.println("hello, {name}")
⟧
```

```rite exec
◆! greet(name) ⟦
  ! @console.println("hello, {name}")
⟧

! greet("world")
```

This carries through the call graph: a function calling a `◆!` function is itself
effectful and needs its own declaration, however deep the host call sits.

## Calling a declared-effectful function without a marker

```rite compile_fail
◆! shout(s) ⟦ ! @console.println(s) ⟧

shout("x")
```

```rite exec
◆! shout(s) ⟦ ! @console.println(s) ⟧

! shout("x")
```

`print` and `println` are host calls under another name, so they take a marker
too: `! println("x")`.

## Passing an effectful function to another one

Handing it over runs it, and nothing on that line would otherwise say so:

```rite compile_fail
◆! shout(n) ⟦ ! @console.println(str(n)) ⟧

[1, 2] → each(shout)
```

```rite exec
◆! shout(n) ⟦ ! @console.println(str(n)) ⟧

! ([1, 2] → each(shout))
```

A lambda written inline already shows its own `!` on the same line, so it needs
no second marker:

```rite exec
[1, 2] → each { |n| ! @console.println(str(n)) }
```

## Naming an effectful function does not hide it

A binding carries the property of what it holds, so a rename is still checked:

```rite compile_fail
◆! shout(n) ⟦ ! @console.println(str(n)) ⟧

◆ run(xs) ⟦
  g ← shout
  each(xs, g)
⟧
```

```rite exec
◆! shout(n) ⟦ ! @console.println(str(n)) ⟧

◆! run(xs) ⟦
  g ← shout
  ! each(xs, g)
⟧

! run([1, 2])
```

## A marker over an expression that performs no effect

`!` is only worth reading if it means something happens. One over an operand that
calls nothing is reported rather than ignored:

```rite compile_fail
x ← ! 42
```

The shape this catches most often is a call written the way Rust writes a macro:

```rite compile_fail
println!("one")
```

That is **two** statements, not a call — a discarded reference to `println`,
then `!` applied to the string — so it used to check clean and print nothing.
The marker goes before the call:

```rite exec
! println("one")
```

The test is whether anything is *called*, not whether the call is effectful.
`! each(xs, f)` for a parameter `f` stays legal, because whether `f` performs an
effect is precisely what Rite cannot always know.

## What the marker does and does not promise

It tells you where effects happen. It does **not** decide what a program may
reach — permissions do, enforced where the capability runs, so a script never
granted `fs:write` cannot write a file however it is called.

The property follows a **name**. A function read from a record field, received as
a parameter, or returned by a call is not tracked, so `each(xs, r.go)` is silent
whatever `r.go` does. Closing that needs effect polymorphism, and so a type system
Rite does not have; `docs/book/effects.md` gives the full boundary.
