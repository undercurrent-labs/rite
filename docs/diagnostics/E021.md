# E021 — an effect needs a marker

Rite marks host effects where they happen. `E021` is raised whenever an effect
would occur without one, in any of four shapes.

## A host call with no marker

```rite compile_fail
@console.println("x")
```

```rite exec
! @console.println("x")
```

## A function whose body performs effects, undeclared

Reported at the declaration rather than at every call, so the fix is one edit:

```rite compile_fail
◆ greet(name) ⟦
  ! @console.println("hello, {name}")
⟧
```

```rite exec
◆! greet(name) ⟦
  ! @console.println("hello, {name}")
⟧

! greet("world")
```

This carries through the call graph: a function calling a `◆!` function is itself
effectful and needs its own declaration, however deep the host call sits.

## Calling a declared-effectful function without a marker

```rite compile_fail
◆! shout(s) ⟦ ! @console.println(s) ⟧

shout("x")
```

```rite exec
◆! shout(s) ⟦ ! @console.println(s) ⟧

! shout("x")
```

`print` and `println` are host calls under another name, so they take a marker
too: `! println("x")`.

## Passing an effectful function to another one

Handing it over runs it, and nothing on that line would otherwise say so:

```rite compile_fail
◆! shout(n) ⟦ ! @console.println(str(n)) ⟧

[1, 2] → each(shout)
```

```rite exec
◆! shout(n) ⟦ ! @console.println(str(n)) ⟧

! ([1, 2] → each(shout))
```

A lambda written inline already shows its own `!` on the same line, so it needs
no second marker:

```rite exec
[1, 2] → each { |n| ! @console.println(str(n)) }
```

## What the marker does and does not promise

It tells you where effects happen. It does **not** decide what a program may
reach — permissions do, enforced where the capability runs, so a script never
granted `fs:write` cannot write a file however it is called. A closure stored in
a binding and passed along later is not tracked; that would need a type system
Rite does not have.
