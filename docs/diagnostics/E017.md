# E017

`?` on a host call that never answers a result. `@fs.exists` answers a bool
and `@clock.sleep` answers none; both are effectful, so the `!` is right and
the `?` looks right beside it — and it used to fail only at runtime, on the
line's first execution.

## Failing example

```rite compile_fail
present ← ! @fs.exists("/tmp")?
```

## Corrected

```rite exec
present ← ! @fs.exists("/tmp")
! @console.println(str(present))
```

Which calls answer results is in the
[capability reference](../generated/capabilities.md), and
`rite describe capability fs` prints the same table.

## Functions you wrote

The same check covers a function declared in your own program, when every path
out of it answers a plain value:

```rite compile_fail
◆! init_schema(conn) ⟦
  ! @db.exec(conn, "CREATE TABLE t(a INTEGER)")?
⟧
c ← ! @db.open(":memory:")?
! init_schema(c)?
```

`init_schema` ends on the *unwrapped* value of `@db.exec`, which is `none` —
so the `?` at the call site has nothing to unwrap. Drop it, or answer
`ok(…)` / `err(…)`.

Only a definite answer is reported. A function whose shape the analysis cannot
pin down — one that returns a parameter, a field, or a pipeline's value, or
one whose exits disagree — is left alone, because refusing a valid program is
worse than missing a bad one.
