# E016 — `?` cannot be applied to a pipeline stage

Postfix `?` binds to whatever sits immediately to its left. In a pipeline that is
the **stage**, not the value flowing through it:

```rite compile_fail
◆ dbl(n) ⟦ ^ n * 2 ⟧

[1, 2] → dbl(0)?
```

There is no useful reading of that. The interpreter took it as "call `dbl(0)`
*without* the piped value, unwrap the answer, then call the answer with `[1, 2]`",
and the compiler backend refused to lower it at all — so the two execution paths
disagreed about a program that compiled. Nothing in the book, the examples or the
fixtures ever used it.

## Put it on the result

`?` belongs where the pipeline's value comes out:

```rite
total ← (rows → map { |r| r.n } → sum)?
```

## Or on the input

If what you are unwrapping is what goes *into* the pipeline, unwrap it first:

```rite
rows ← (! @json.read(path))? → keep { |r| r.active }
```

## Why not just short-circuit the pipeline?

Because stages do not short-circuit at all — a `Result` travels through a pipeline
as an ordinary value, and `and_then` is the opt-in that stops on `err`. Making `?`
mean "short-circuit from here" would put a second, invisible control-flow rule
inside an operator whose whole appeal is that you can read it top to bottom. See
[Pipelines](../book/pipelines.md) for the full behaviour.
